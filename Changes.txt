	withdrawn (the mem debug tail magic sits fully inside the allocation
	and the two-step getregiondata is the documented pattern), the
	small-pool alignment note was downgraded to a comment fix, and the
	confirmed set ships here.
	drag and drop: every wm_dropfiles now ends in dragfinish - the shell
	file list leaked on every drop. the clipboard file-list paste reuses
	the same handler without finishing the clipboards own hdrop (which
	would corrupt clipboard memory).
	memory safety: a null free crashed inside heapsize before the invalid
	free guard could run; the glyph cache eviction copied overlapping
	arrays with memcpy; the clipboard dib paste now applies the same
	pixel budget as the file loaders and no longer truncates the copy
	size to int (os_copy_memory and os_move_memory take size_t lengths).
	registry: the add/remove programs entry is written to the 64-bit view
	and removed with regdeletekeyexw (regdeletekeyw cannot reach the
	alternate view; the nsis probe already used setregview 64), with the
	legacy wow6432node copy swept on uninstall.
	webp animations: each frame now carries its own duration from a
	container scan - the old loop handed every frame the gap to the
	previous one and the last frames duration never existed.
	touch: the digitizer probe asks for a touch screen (not just any ready
	digitizer), gid_begin and gid_end reach defwindowproc as msdn requires,
	and the press-and-hold and flick system gestures are disabled for the
	window.
	robustness: the ini reader refuses files over 16 mb, a failed utf-8
	config conversion no longer reads an unterminated buffer, bad
	localization ids clamp to a fallback instead of an out-of-bounds read
	in release builds, and the safe_size wchar multiply comment no longer
	says addition.

Stable: Version 1.1.03 (magnifier pill round)
	pill icons: the zoom magnifier glyphs are redrawn. the zoom in/out
	strokes declared three point polylines over two element arrays, so the
	renderer walked one element past each array and drew a stray tail line
	to whatever coordinate pair lived in the adjacent memory (the crooked
	cross and handle in the field screenshots), the hand written 21 point
	ring wobbled between radii 12.65 and 13.6 which read as a lumpy lens at
	the pill sizes, and the cross strokes collapsed into capped smudges at
	the small toolbar sizes. the ring is now a true gdi+ ellipse primitive
	(drawn through gdipdrawellipse, not a sampled polyline), the counts
	match the arrays, the handle starts exactly on the 45 degree ring
	point, and the cross grew one grid unit longer and one wider.
	pill shape: the zoom buttons and their tray are true stadium capsules
	now (roundrect with half height end radii) with breathing room between
	the buttons - the old zero gap layout packed both square borders back
	to back in the middle (a double line) and the blocky pair sat next to
	the flat toolbar like a patch from another toolkit. the glyph padding
	follows the button height so all four sides stay even at every dpi.
	toolbar icons: the toolbar image list keeps the 32bpp alpha channel
	(ilc_color32) - the old 24 bit list with a mask binarized the
	antialiased glyph edges and washed the toolbar icons into a pale gray
	while the zoom pill drew the same glyphs from the raw icons at full
	contrast (the two-tone toolbar the field screenshots caught).
	dark strip: the rebar strip behind the centered toolbar now carries
	the dark chrome face - the rebar window was registered with the light
	window class brush, so the slabs on both sides of the toolbar stayed
	white in dark mode (the big white rectangle the field screenshots
	caught in the menu bar row).
	version order: the release series returns to the 1.1 line as the
	leading one, so the tag ladder reads 1.0.03, 1.0.04, 1.1.02, 1.1.03 -
	strictly increasing, no duplicates, nothing deleted.

Stable: Version 1.0.04 (pointer width budget)
	load performance: the pixel budget ceiling is now pointer width
	dependent. 32-bit builds keep the 100 mp guard (a 100 mp rgba
	frame is already 400 mb against a 2 gb address space) while
	64-bit builds (x64 and arm64) raise the ceiling to 400 mp, so
	real panoramic stitches and large flatbed scans load normally
	instead of failing like a corrupt file - the reported 1.0.03
	regression where big-but-honest images stopped opening.
	budget diagnostics: both loaders now print the refusal reason
	(the claimed megapixels and the ceiling) through the debug
	channel, so a user wondering why a file fails can turn the debug
	banner on and read it - silent refusals are over.
	test kit: the anomaly sample set grows to 38 samples - 35 now
	doubles as the x64 acceptance boundary (110 mp loads on x64,
	still refused on 32-bit) and 38 pins the x64 refusal point
	(625 mp lying header). the guard suite pins both branches of
	the ceiling split and the diagnostic on both loaders.
